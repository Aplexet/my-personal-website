From Chatbots to Multi-Agent Systems: My First Vibe Coding Experience

Published July 31, 2026

Before this week, I mainly thought of AI as a chatbot that answers questions. I had used tools such as ChatGPT, but I did not understand how an AI system could inspect information, use tools, follow a workflow, or cooperate with other agents. Building my own system changed that idea completely.

From Answering to Acting

A chatbot usually follows a short path: it receives a question, sends it to a language model, and returns text. An AI agent goes further. It observes data, reasons about a task, chooses a tool, takes an action, and checks the feedback. The language model can suggest and explain a decision, while Python performs exact work such as calculations, validation, and data processing.

Why Build an AI Team?

If one agent can handle many tasks, why use several? I learned that the answer is specialization. A multi-agent system is not a collection of chatbots repeating the same answer. Each agent needs a different responsibility, the information required for that role, and a clear output for the next stage. This resembles an AI co-scientist: one role generates an idea, another criticizes it, and another improves it.

AgentInformation It SeesMain Responsibility
Alpha AgentTechnical indicatorsPropose possible trades
Risk AgentCandidates and portfolioApprove, reject, or limit ideas
Portfolio AgentApproved ideas, prices, and cashCalculate affordable orders

What I Built in Three Stages

I began with a rule-based agent. It read a market snapshot and returned buy, sell, or hold. For example, it could buy about $200 of an approved stock when RSI was below 35 and its price was between $0 and $250. Its valid-symbol list and position limit made it predictable. That simplicity made it a useful baseline because I could always explain why an action occurred.

if rsi < 35 and 0 < price < 250:
    action = "buy"
else:
    action = "hold"

Next, I gave one language-model agent several market indicators and asked for structured output: an action, symbol, confidence, reasoning, and position size. It was more flexible and could explain its choice, but flexibility also created risk. It could omit a field, invent a symbol, or recommend an unsafe size. A strict schema helped, yet deterministic Python still had to check every proposal before accepting it.

Finally, I separated the work into Alpha, Risk, and Portfolio agents. Alpha searched for opportunities without seeing cash or current holdings. Risk reviewed candidates against conviction and portfolio rules. Portfolio received only approved ideas and converted them into whole-share orders that stayed within available cash. Giving each role less information actually made the complete system easier to inspect.

How Vibe Coding Helped

Vibe coding did not mean asking AI to write everything at once. My loop was: give context, request one small change, run the code, read the result, send back the error, and revise. I first made a script that ran, then returned one hold action, added a rule, introduced an LLM call and structured output, built each specialized agent, connected them, and printed an execution trace.

The quality of the code depended on the contract I provided: the Python library, market-snapshot shape, valid symbols, required fields, capital limits, and file setup. When something broke, sharing the full traceback and asking for only the broken part to be fixed was much more useful than restarting. Small testable steps made it possible to understand each change before keeping it.

Watching the Handoffs

Alpha proposed
AAPL — Buy — Confidence 0.72
KO — Buy — Confidence 0.48

Risk reviewed
AAPL — Approved
KO — Rejected: confidence below 0.55

Portfolio created
Buy 1 share of AAPL

This trace made the system understandable. Alpha produced two candidates, Risk rejected one for a visible reason, and Portfolio turned the remaining idea into one affordable order. Seeing every handoff was more educational than seeing only the final trade.

What Went Wrong

My first problem was output that counted as valid JSON but omitted position_size. I learned that valid syntax does not guarantee a complete contract. Another problem was a confidence value of 4 when the next agent expected a decimal between 0 and 1. Agents must agree on both field names and the meaning of their values. I also saw how one role could return thesis while the next expected reasoning. The interface between agents can be just as important as the intelligence inside them.

These issues showed why a human still has to read generated code, protect API keys in a .env file, keep that file out of Git, validate symbols, verify calculations, and reject changes that are not understood. More agents do not automatically create a safer or smarter system.

Comparing the Approaches

ApproachMain StrengthMain Limitation
Rule-based agentFast, predictable, and easy to inspectLimited to fixed rules
Single LLM agentFlexible and able to explain decisionsOne model handles too many responsibilities
Multi-agent pipelineClear roles and visible decision stagesSlower and harder to coordinate

The multi-agent pipeline did not guarantee the highest return. Its real advantage was a decision process divided into stages that I could inspect, test, and debug. Better explanations and more complexity do not automatically produce better trading performance.

What I Learned

  • An agent combines reasoning, tools, actions, and feedback.
  • Multiple agents need specialized roles instead of repeated responsibilities.
  • Clear input and output contracts make handoffs reliable.
  • Deterministic code should enforce numerical and safety rules.
  • Vibe coding works best through small changes that can be tested.
  • AI-generated code still requires careful human review.

Conclusion

At the beginning of the week, I viewed AI mainly as a tool for answering questions. After building this pipeline, I understood agents as parts of a larger system. My biggest lesson was not how to generate more code. It was how to divide a complicated task into roles, define clear interfaces, study failures, test each stage, and keep a human in control.
